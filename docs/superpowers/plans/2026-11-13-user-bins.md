# User Bins Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Let any user make public or private album bins whose records feed every user's predictions, browse others' public bins by popularity, and find bins in search — on web and iPhone.

**Architecture:** User bins reuse the curated `Bin` / `BinEntry` / `BinTrack` tables (`kind='user'`). Pure rules (limits, validation, visibility, ordering, the For You draw) live in a new `backend/user_bins.py` so they test without a database; `backend/routers/bins.py` gains the owner-only write endpoints. One SQL fragment decides which bins count toward predictions, and all five pipeline readers of `binentry` use it. Clients share the API and sectioning in `shared/`.

**Tech Stack:** FastAPI + SQLModel (Postgres), pytest (no DB connection), React 19 + Tailwind 4 (web), Expo / React Native (mobile), `@pressd/shared`.

**Spec:** `docs/superpowers/specs/2026-11-13-user-bins-design.md`

## Global Constraints

- Albums and EPs only (`item_type='album'`); never a single (≤ 2 tracks, `scoring.is_single_release`) and never an unreleased record (release date after today).
- `MAX_ENTRIES = 100` per bin; `MAX_BINS_PER_USER = 25`; title ≤ 80 chars (*plan's call*), description ≤ 500, note ≤ 280; whitespace folded, empty description/note stored as null.
- Visibility `private` | `published` (UI says **Public**); new bins are `private`. No `unlisted` for user bins.
- Every bin counts toward predictions, private included, **except** a bin with `hidden_at` set.
- Hidden after `REPORTS_TO_HIDE = 5` distinct reporters; a reporter never sees that bin again.
- Popularity = distinct non-owner viewers in the last 30 days; ties and zero → newest `updated_at`.
- Account deletion: private bins deleted; published bins kept with `owner_id = NULL` ("a former Pressd member"). `bintrack` rows go before their `binentry`.
- No likes, comments, follows or notifications on bins.
- Covers: uploaded image stored square through `users._normalize_image` (`BIN_COVER_SIZE = (800, 800)`), else the 2×2 mosaic.
- Web and iPhone ship together (CLAUDE.md §1). CLAUDE.md §5 Bins updated in the same commits.
- Commits: declarative sentences, **no Co-Authored-By lines** (Jack's rule).
- Local `.env` points at production: never start uvicorn with new migration lines without saying so; `init_db()` adds `bin.cover_url` on the next boot.

## Review Focus

1. **Someone else's private bin leaking** — through `GET /bins/{slug}`, `scope=community`, `scope=for_you`, search, or a report on it. Expect 404 / absent everywhere. Tests in Tasks 1, 3, 4.
2. **A deleted account with bins** — the delete must not fail on `bintrack`'s foreign key, and a published bin must survive ownerless and still render. Tests in Task 1 (delete order) and Task 3 (`owner` null in the payload).
3. **Reorder with a stale or partial id list** (ids missing, duplicated, or from another bin) — reject with 400, never half-apply against `UNIQUE(bin_id, position)`. Test in Task 3.
4. **Adding the same record twice in different editions** ("Take Care" and "Take Care (Deluxe)") — one `subject_key`, so 409. Test in Task 1.
5. **A hidden bin still steering predictions or the audio queue** — the counting fragment must be in all five readers. Test in Task 2.

**Files:**

**Interfaces:**
- Produces (in `backend/user_bins.py`):
  - constants `MAX_ENTRIES=100`, `MAX_BINS_PER_USER=25`, `TITLE_MAX=80`, `DESCRIPTION_MAX=500`, `NOTE_MAX=280`, `REPORTS_TO_HIDE=5`, `POPULAR_DAYS=30`, `BIN_COVER_SIZE=(800, 800)`, `VISIBILITIES=("private","published")`
  - `clean_text(raw, limit: int, *, required: bool) -> str | None` — folds whitespace; raises `ValueError` over `limit` or when required and empty.
  - `new_slug() -> str` — `"u-" + 10 lowercase base36 chars` (matches `bins.SLUG_RE`).
  - `can_view(bin_kind: str, owner_id: int | None, visibility: str, hidden_at, viewer_id: int, blocked: set[int], reported: set[int], bin_id: int) -> bool` — the owner always (their own hidden bin included); a curated bin always; anyone else only a published bin that isn't hidden, whose owner isn't in `blocked`, and that they haven't reported.
  - `addable_release(release_date: date | None, track_count: int | None, album_name: str, today: date) -> str | None` — returns the refusal reason (`"unreleased"`, `"single"`) or None.
  - `community_order(rows: list[tuple[int, int, datetime]]) -> list[int]` — rows of `(bin_id, viewers, updated_at)` → ids, viewers desc then `updated_at` desc.
  - `for_you_pick(curated: list[int], community: list[int], rng: random.Random, n: int = 3) -> list[int]` — first curated id (by given order) first, then up to `n-1` random community ids, curated fill if short.
  - `validate_order(current_ids: list[int], requested: list[int]) -> list[int]` — same set, no duplicates, else `ValueError`.
  - `COUNTING_BINS_SQL = "b.hidden_at IS NULL"` and `COUNTING_ENTRY_JOIN = "JOIN bin b ON b.id = e.bin_id AND b.hidden_at IS NULL"` (string fragments for Task 2).
- Produces (models): `BinCover(bin_id PK FK bin.id, content_type, data LargeBinary, updated_at)`, `BinReport(id, user_id FK, bin_id FK, reason Optional[str], created_at; UNIQUE(user_id, bin_id))`, `BinView(bin_id FK, user_id FK, viewed_at; PK(bin_id, user_id))`, `Bin.cover_url: Optional[str]`.

### Task 3: The bins API for owners, viewers and reporters

**Files:**
- Modify: `backend/routers/bins.py`
- Test: `tests/test_bins.py` (extend)

**Interfaces:**
- Consumes: Task 1's helpers and models; `albums.create_copy`'s resolve shape (`/search/resolve` dict: `album_name`, `artist`, `year`, `release_date`, `tracks`, `deezer_id`, `art_url`, `genre`); `tracklink.link_bin_entries(con, entry_ids=[id])`; `users._normalize_image`; `blocks.blocked_ids`; `subject_key_album`.
- Produces (all behind `current_user`; owner-only routes 404 for non-owners so private bins can't be probed):
  - `GET /bins?scope=curated|mine|community|for_you` (default `curated`, today's behaviour). Cards add `kind`, `visibility`, `owner` (`public_user` or null), `cover_url`, `can_edit`.
  - `POST /bins` `{title, description?, ranked?=true, visibility?='private'}` → card; 409 at 25 bins.
  - `PATCH /bins/{slug}` same fields; `DELETE /bins/{slug}`.
  - `POST /bins/{slug}/entries` `{album_id}` (one of the caller's copies) **or** `{release}` (a resolve dict) → entry; 400 `unreleased` / `single`; 409 duplicate `subject_key` or at 100; then `link_bin_entries` for it; bumps `entry_count`, `updated_at`.
  - `PATCH /bins/{slug}/entries/{id}` `{note}`; `DELETE /bins/{slug}/entries/{id}` (re-packs positions).
  - `PUT /bins/{slug}/order` `{entry_ids: [...]}` — `validate_order`, then two-phase position write (negatives, then final) in one transaction; `rank = position+1` when `ranked`, else null.
  - `POST /bins/{slug}/cover` (multipart `file`), `DELETE /bins/{slug}/cover`, unauthenticated `GET /bins/{slug}/cover` (bytes, as avatars and banners are served, since an `<img>` can't carry a header — *plan's call*: it checks nothing, and the URL, with a `?v=` stamp, is only handed to people who can see the bin).
  - `POST /bins/{slug}/report` `{reason?}` — upsert `BinReport`; at 5 distinct, set `hidden_at`; `{ok: true}`; reporting your own bin is 400.
  - `GET /bins/{slug}`: uses `can_view`; records a `BinView` (upsert `viewed_at=now()`) when the viewer isn't the owner; payload adds `kind`, `visibility`, `ranked`, `owner`, `can_edit`, `cover_url`, and each entry's `note` (user bins; curated keep `blurb`).
